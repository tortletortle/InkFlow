# 水墨时序表达引擎研究（Ink Animation Engine）

> 研究对象：墨生 InkFlow  
> 研究日期：2026-11-21  
> 研究状态：技术路线研究；尚未进入生产实现  
> 核心命题：让水墨本身承担动画表达，而不是给普通动画叠加一层静态水墨滤镜。

## 1. 结论先行

墨生下一阶段的核心不应只是继续增加山脊纹理、生态物种或着色器噪声，而应建立统一的**水墨时序表达引擎（Temporal Ink Animation Engine）**。

这套引擎由三个不可分割的部分组成：

1. **运动语义（Motion）：** 场景中什么在运动、向哪里运动、速度多大、属于哪种事件。
2. **笔墨结构（Stroke）：** 用什么笔触表达对象，笔锋方向、宽度、浓淡、断续、起收笔和留白如何安排。
3. **媒介动力学（Medium）：** 水如何携墨流动，墨如何扩散、积聚、沉积、干燥，以及如何受纸纤维和地形影响。

核心原则：

- 运动决定墨迹的方向与变化；笔墨决定运动如何被观看者理解；水墨介质决定变化的质感。
- 不能每帧独立随机生成纹理，否则会闪烁；笔触必须有稳定身份、稳定坐标和连续时间状态。
- 不能把所有对象都做成流体。山石以结构性笔触为主，流水以方向性流动笔触为主，云雾以水分扩散为主，树木以生长笔序和局部风致变形为主。
- 留白不是未完成区域，而是构图和运动表达的一部分。
- 物理模拟服务于艺术表现，不追求无必要的完整流体力学。

## 2. 对 V1.17 现状的代码审计

审计对象：[InkFlow_V1.17.html](../../InkFlow_V1.17.html)。

### 2.1 已有基础

| 模块 | 当前能力 | 对新引擎的价值 |
|---|---|---|
| `InkFlow` | 纸面网格上有水量 W、游离墨 M、固定墨 P、纸纹与纤维方向；支持落墨、毛细迁移、浓度扩散、蒸发、吸附和沉积 | 可复用为纸面媒介模拟核心 |
| `InkArt` | 程序化山水、树木、岛屿、笔触与纸纹 | 可提供笔触模板与构图素材 |
| `LivingScene` | 瀑布笔线、雾层、鸟、波纹、船等按时间变化 | 已有动画事件与场景层，可逐步替换为水墨驱动 |
| `EcoSim._flow` | 计算降雨径流，并保存 `flowOut`、`flowTo`、`flowDominant` | 可为流水笔触和携墨方向提供真实的模拟驱动 |
| `InkPigment.advance` | 地表墨色根据坡度、含水量和邻格浓度迁移，并记录质量变化 | 是地表墨色输运的初步基础 |
| `Terrain3D` | WebGL 3D 地形、山脊方向属性、片元水墨纹理、软件渲染回退 | 可作为最终空间渲染后端 |

### 2.2 当前缺口

**缺口 A：纸面物理与三维世界分离。**  
`InkFlow` 的 W/M/P 介质状态运行在独立的 2D 画布网格上；三维生态世界另有 `surfaceInk`。两套状态尚未统一为一个媒介接口。

**缺口 B：地表“墨随水行”还没有真正跟随水流通量。**  
当前 `InkPigment.advance` 用邻格高度差、湿度和墨量差计算迁移；它没有读取 `EcoSim._flow` 已计算的 `flowOut/flowTo`，所以它是坡度/湿度驱动的近似扩散，不等同于沿实际径流通量携墨。

**缺口 C：地表墨迹主要表现为颜色变深。**  
`surfaceInk` 在地形重建时映射到顶点颜色；尚没有完整的游离墨/固定墨分离、湿边沉积、动态墨晕、起笔收笔或运动笔锋。

**缺口 D：已有动画多数是对象/图层运动，不是墨迹介质动画。**  
`LivingScene` 中雾、波纹、瀑布线、鸟和船已有程序化运动；但笔触本身没有完整的水分、墨量、干燥和沉积生命周期。3D 着色器的时间变量主要控制雾化/大气变化，不代表山体墨迹正在生长或流动。

**缺口 E：缺少统一的时序连续性约束。**  
随机纹理若按屏幕像素或每帧重新采样，容易出现纹理游移和闪烁。需要对象局部坐标、世界坐标、固定笔触 ID 和时间连续状态。

## 3. 研究依据

### 3.1 中国画流水：少量笔线沿稳定流线运动

Zhang 等人的《Video-Based Running Water Animation in Chinese Painting Style》先估计视频光流，再分析流动方差以放置稳定流线，最后让少量具有中国画笔触模板的笔线沿流线连续运动。它强调流水不是每帧重新画一张，而是先建立流动结构，再让笔触沿结构运动。

对墨生的启示：

- 直接使用生态水文流场建立河道流线。
- 平稳区域使用少量、较长、连续的线；湍急区域减少长线，改用短促飞白、墨点和水花。
- 笔触宽度、间距、速度、浓度应由水流状态控制。
- 流线本身稳定，流动笔触沿线前进，避免逐帧随机重排。

论文：[Tsinghua PDF — Video-Based Running Water Animation in Chinese Painting Style](https://cg.cs.tsinghua.edu.cn/papers/tr080801.pdf)。

### 3.2 真实媒介动态：把“墨如何扩散”也作为动画信号

《Fluidymation: Stylizing Animations Using Natural Dynamics of Artistic Media》（Computer Graphics Forum, 2021）不是只使用一张静态水彩纹理，而是记录颜料在湿纸上扩散的动态样本，再把样本的外观和动态特征迁移到目标运动上。论文指出，逐帧独立风格化容易闪烁；过度锁定纹理又会让纹理像贴在物体表面。其方法同时考虑运动方向、运动量、时间连续性和纹理多样性。

对墨生的启示：

- 不仅要保存一张笔触贴图，还要保存笔触从湿到干的动态样本。
- 物体运动应驱动墨迹的移动方向和速度，媒介自身的扩散负责局部过渡。
- 既不能让墨迹完全粘死在屏幕上，也不能让纹理无约束漂移。
- 可以先用确定性程序模拟，之后再用真实拍摄的水墨扩散短视频做样本库。

论文：[Fluidymation — Eurographics / Computer Graphics Forum PDF](https://diglib.eg.org/bitstream/handle/10.1111/cgf14398/v40i7pp021-032.pdf)。

### 3.3 笔触生成顺序：动画需要符合中国画的组织规律

Tang 等人的《Animated Construction of Chinese Brush Paintings》（IEEE TVCG, 2018）研究从静态中国画重建绘制顺序，将笔触组织为阶段，再优化绘制顺序，使动画构成符合艺术组织规则。

对墨生的启示：

- 山水显形不能简单整体淡入；需要先后层次、远近关系和笔触顺序。
- 山体轮廓、皴法、苔点、树干、枝叶和水纹应有不同的生成阶段。
- 需要“画面构成顺序”，而不是对所有对象使用同一个动画曲线。

论文：[University of Konstanz — Animated Construction of Chinese Brush Paintings](https://graphics.uni-konstanz.de/publikationen/Tang2018AnimatedConstructionChinese/index.html)，DOI: 10.1109/TVCG.2017.2774292。

### 3.4 视频风格迁移：实例级分层和多帧融合

IJCAI 2021 的《Instance-Aware Coherent Video Style Transfer for Chinese Ink Wash Painting》指出，中国水墨视频风格迁移的困难之一是时间一致性与自由笔触特征之间的冲突。其方案采用多帧融合和实例感知风格迁移，并根据实例分割选择前景表达尺度、保留背景留白。

对墨生的启示：

- 山体、树木、动物、流水、云雾应分别处理，不能全画面统一套滤镜。
- 需要把主体遮罩、深度、运动和背景留白作为不同控制通道。
- AI 视频风格迁移可用于离线素材实验，但不应成为交互式世界的实时核心依赖。

论文：[IJCAI 2021 — Instance-Aware Coherent Video Style Transfer for Chinese Ink Wash Painting](https://www.ijcai.org/proceedings/2021/114)。

### 3.5 3D 动画的水彩表达：对象空间与图像空间协同

《Art-directed watercolor stylization of 3D animations in real-time》研究在 3D 对象空间中控制手绘扰动、颜料湍动、颜色渗化、边缘积色、表面扭曲和纸纹颗粒，再结合图像空间效果。其价值在于证明艺术家可以局部控制风格，而不是依赖全屏后处理。

对墨生的启示：

- 山体墨迹优先锚定地形对象坐标/UV。
- 云雾和水汽可以使用世界空间/流场坐标。
- 镜头变化时，笔触应稳定附着于对象或介质，而非随屏幕像素滑动。
- 允许艺术控制参数覆盖纯物理结果。

论文：[Art-directed watercolor stylization of 3D animations in real-time](https://www.sciencedirect.com/science/article/pii/S0097849317300316)。

## 4. 建议的统一架构

建议建立五个模块，不把现有所有功能推倒重写。

### 4.1 MotionField：运动语义场

输入来自生态模拟和对象动画：

- 位置、速度、方向、加速度；
- 水流通量、坡度、湿度；
- 对象 ID、对象局部坐标、遮罩和深度；
- 事件：生长、降雨、冲刷、移动、碰撞、出生、消亡。

第一阶段直接复用 `EcoSim._flow` 的流量信息；为每个格点增加由实际出流贡献计算的二维方向向量，而不是仅靠坡度猜方向。

### 4.2 StrokeGraph：笔触结构图

每条笔触使用稳定 ID 和参数化骨架：

`Stroke = {id, objectId, curve, widthProfile, opacityProfile, brushType, seed, progress, pigmentLoad, waterLoad, age}`

关键参数：

- 曲线骨架与方向；
- 起笔、行笔、转锋、收笔；
- 沿线宽度、压力、浓淡和干湿；
- 边缘破碎、飞白、纸纹采样；
- 笔触在对象局部坐标中的绑定关系。

笔触库不能只存随机噪声贴图；应从真实笔触扫描/拍摄中提取轮廓、骨架、宽度变化、横向浓度分布和纸纹破碎特征。

### 4.3 InkMedium：水墨介质状态

统一维护：

- `W`：局部含水量；
- `M`：可移动墨；
- `P`：已固定/干燥墨；
- `F`：纸纤维方向与吸水性；
- `E`：湿边/边缘沉积；
- `U`：介质速度场。

推荐采用可控的二维有限体积/半拉格朗日混合模型，而不是一开始就做完整 Navier–Stokes：

[
partial_t M + 
ablacdot(Mmathbf{u})
= 
ablacdot(D(F,W)

]

[
partial_t P = k_b(W)M + k_e(W,

]

其中 (mathbf{u}) 由真实水流或对象运动提供；扩散张量 (D) 可沿纸纤维方向和水流方向各向异性；(k_b) 表示墨固定/干燥，(k_e) 表示湿边沉积。固定墨原则上不再随水流移动。

地表水墨应优先采用水文模型产生的通量 (q_{ij}) 携带游离墨：

[
f_{ij}=q_{ij}rac{M_i}{W_i+epsilon}
]

这能把“墨随水行”从坡度启发式改成与实际径流通量耦合的过程。需要对通量进行 donor 限制/CFL 限制，保证非负性和质量守恒。

### 4.4 InkRenderer：水墨渲染器

分两条路径：

- **2D 纸面：** 复用 Canvas/ImageData 和现有 W/M/P 模型；笔触用带宽度、透明度和纸纹的参数曲线渲染。
- **3D 地形：** 继续使用 WebGL。建议将水、游离墨、固定墨、湿边编码到一张低分辨率 RGBA8 状态纹理，通过地形世界坐标采样；每个模拟步更新纹理，不必为了墨迹变化重建整块地形网格。WebGL1 可先用 RGBA/UNSIGNED_BYTE 路径，避免依赖浮点纹理扩展。

纹理坐标必须稳定地绑定到地形/对象坐标。屏幕空间后处理只作为辅助，不作为主表达。

### 4.5 InkDirector：动画导演/规则映射

将生态事件转换为笔墨动作：

`event -> motion field -> stroke plan -> medium update -> render`

导演负责选择笔法、密度、速度、停顿、留白和生成顺序；物理层只提供可信的运动与干湿变化，不决定全部艺术结果。

## 5. 不同对象应该使用不同的水墨动画语法

| 对象/事件 | 主要表达 | 不应该做成 |
|---|---|---|
| 山体出现 | 远山先淡后浓；主轮廓、皴法、苔点分阶段显形 | 全山统一透明度淡入 |
| 山石/山脊 | 稳定骨架笔触、顺势皴、积墨与局部干笔 | 每帧变化的随机噪声 |
| 河流 | 沿水文流线移动的少量长笔；急流处断笔、飞白和水花 | 整片水面平移纹理 |
| 瀑布 | 从源头向下连续行笔，速度影响笔线长度和断续，底部形成散点与涟漪 | 几条固定白色线条循环平移 |
| 云雾 | 水分扩散、缓慢平流、边缘消散和层间遮挡 | 单张模糊贴图左右移动 |
| 树木生长 | 主干、枝杈、叶点按生长顺序生成 | 树模型整体缩放出现 |
| 树木受风 | 枝条骨架轻微弯曲，笔触随局部骨架变形，墨迹不发生无意义滑动 | 整棵树刚体摇摆 |
| 动物 | 身体轮廓与关键结构用少量笔触跟随骨骼/姿态；足迹和短暂墨迹随环境湿度衰减 | 直接把动物变成黑色小圆点 |
| 降雨 | 雨线、落点、涟漪、地表润湿；已有墨迹受水影响而晕开 | 单纯增加屏幕粒子 |
| 枯萎/消亡 | 由浓转淡、断笔、干裂和留白逐步显现 | 瞬间删除对象 |

## 6. 一条笔触的完整生命周期

建议把每个动画笔触统一为以下状态机：

1. **起笔/显形：** 沿骨架逐步揭示笔触，宽度和墨量由压力曲线控制。
2. **行笔/随动：** 笔触沿目标运动场推进或随对象局部骨架变形。
3. **洇化/渗透：** 游离墨在湿度场中扩散，边缘产生羽化与局部积墨。
4. **收笔/干燥：** 水分减少，游离墨转为固定墨，留下枯笔、飞白和纸纹颗粒。
5. **留存/消退：** 静态结构墨长期保留；云雾、水痕、足迹等短期墨迹按对象类型衰减或被新笔触覆盖。

并非每条笔触都要经历全部状态：山石结构线可直接进入留存，水雾则以扩散和消退为主。

## 7. 第一阶段实验：瀑布与河流

不建议一开始同时重构山、树、云、动物。先做一个可以被严格比较的最小实验。

### 7.1 对照组

固定同一地形、相机、随机种子、河流速度和画面分辨率：

- A：当前静态水墨纹理/固定瀑布线；
- B：只让笔触沿流线运动；
- C：笔触运动 + 水墨介质扩散/沉积；
- D：在 C 的基础上加入真实笔触样本/动态扩散样本。

### 7.2 验证指标

| 指标 | 检查内容 |
|---|---|
| 运动方向一致性 | 笔触切线与水流速度向量的夹角 |
| 时间连续性 | 相邻帧运动补偿后的闪烁/纹理跳变 |
| 介质质量守恒 | 游离墨、固定墨与边界流失的质量账本 |
| 形态表达 | 平稳水流是否形成连续长笔，急流是否自然断裂 |
| 留白 | 水墨是否过度覆盖背景，是否保留空白水面 |
| 性能 | 2D/3D 分辨率下的模拟耗时、纹理上传耗时和实际帧率 |
| 艺术评价 | 同条件 A/B 盲评：是否更像中国水墨动画，而不只是更复杂 |

所有实验使用多个随机种子；性能和画质分开验收。任何单个异常先复现，再判断是否系统性问题。

### 7.3 第一阶段验收目标

- 河流笔触稳定跟随实际水文流向，而不是仅跟随地形下坡方向。
- 同一笔触在连续帧中身份不变，不闪烁、不随机跳位。
- 湿墨能移动，干墨能沉积；两者状态可观察、可复现。
- 平稳流段和急流段呈现不同笔法。
- 画面有明显留白，不以全屏噪声覆盖画面。
- 2D 与 3D 使用同一套笔触/媒介状态定义，渲染方式可以不同。

## 8. 开发顺序建议

1. **先做 2D 瀑布/河流实验台：** 快速验证笔触骨架、运动场、墨水扩散和干燥的组合，不先动主场景。
2. **把 EcoSim 水文流量接入墨输运：** 使用实际水通量携带游离墨，保留质量账本。
3. **建立稳定的 StrokeGraph 和笔触样本库：** 从少量高质量真实笔触开始，不使用大量廉价随机纹理。
4. **接入 3D RGBA8 墨状态纹理：** 先让山体、河流和坡面墨迹在相机移动时保持空间稳定。
5. **扩展到云雾、树木和动物：** 每类对象单独设计笔墨语法，不做一套参数通吃所有对象。
6. **最后再考虑视频扩散模型：** 主要用于离线生成/筛选笔触动态参考，不作为交互主循环的必需组件。

## 9. 明确不采用的捷径

- 不把普通三维画面统一做灰度化、边缘描线、模糊和噪声叠加后称为水墨动画。
- 不让每帧重新随机生成笔触纹理。
- 不让所有对象都以同一种方式“墨迹扩散”。
- 不让水墨物理模拟单独决定构图；构图和笔法需要艺术规则及人工控制。
- 不为追求物理真实性而引入完整流体求解器，除非实验明确证明简化模型无法满足效果。
- 不先训练/接入视频生成模型来替代可控的实时动画引擎。
