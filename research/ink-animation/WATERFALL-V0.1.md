# 水墨瀑布时序实验 V0.1

- 项目：墨生 InkFlow
- 分支：research/ink-waterfall-v0.1
- 状态：独立实验原型；未合并主线，未完成真实浏览器视觉验收
- 日期：2026-11-21

## 1. 研究问题

验证水墨动画能否由“运动笔触 + 水墨介质状态”共同产生，而不是通过全屏滤镜或每帧随机纹理伪造运动。

本实验先选择瀑布，因为它同时具备清晰的流动方向、稳定的边界、飞溅区域和大量可利用的留白。

## 2. 核心艺术决策：水是留白

瀑布主体不应被填成黑色墨带。实验将水体主体保留为宣纸留白；墨迹负责表现：

- 瀑布两侧岩壁与水线边界；
- 随流向下的细笔触；
- 湿纸边缘的晕染和积墨；
- 底部飞溅、涟漪与淡墨；
- 岩石的结构、皴法和枯笔。

动态水流的可读性来自边缘笔触、短暂的水纹和底部飞溅，而不是将水体涂成黑色。

## 3. 实验内容

### 3.1 四种对照模式

| 模式 | 内容 | 目的 |
|---|---|---|
| A 静态基线 | 固定轮廓和留白 | 作为静态表现基线 |
| B 流动笔触 | 稳定 ID 的笔触沿曲线向下运动 | 检查笔触运动是否连贯 |
| C 墨水介质 | 水分输运、颜料扩散、边缘沉积和干燥 | 检查介质状态是否带来动态变化 |
| D 综合表达 | B + C | 检查运动与媒介耦合后的整体表现 |

### 3.2 笔触结构

每条程序化笔触拥有稳定 ID、左右侧别、曲线偏移、相位、速度、长度、宽度、浓度、飞白参数和确定性随机种子。每帧根据同一笔触状态更新位置，不重新随机生成笔触。

当前笔触是算法占位素材，不是最终美术资源。后续需要使用真实毛笔/宣纸扫描素材提取骨架、宽度剖面、边缘破碎和墨色分布。

### 3.3 介质模型

ink-medium.js 提供 InkMedium2D，使用二维网格维护：

- water：局部含水量；
- mobile：游离墨；
- fixed：已沉积/固定的墨；
- fiberX/fiberY：纸纤维方向；
- vx/vy：外部提供的运动速度场。

主要过程：

1. 按网格面计算有方向的水分通量；
2. 游离墨按供体浓度随水通量迁移；
3. 采用受供体限制的浓度扩散；扩散系数受纸纤维方向影响；
4. 水分蒸发；
5. 游离墨按干燥程度和局部含水梯度沉积为固定墨。

水分和墨量均使用质量账本。固定墨不再随水流移动。水分蒸发不会直接删除墨量。

这是用于艺术动画的保守有限体积近似，不是经实验标定的真实纸张/墨汁模型，也不是完整 Navier–Stokes 求解器。

## 4. 当前实现与边界

已实现：

- 独立 Canvas 2D 瀑布场景；
- 宣纸纹理、远近山层、两侧岩壁、瀑布留白和底部水潭；
- A/B/C/D 四种对照模式；
- 稳定 ID 的程序化运动笔触；
- 纸纤维方向影响的各向异性扩散；
- 水分输运、游离墨输运、扩散、蒸发、固定墨沉积；
- 连续水源/墨源补给；
- 帧率、活动笔触数、水量误差和墨量误差显示；
- 可在 Node.js 中运行的独立数值测试。

尚未实现：

- 真实毛笔、宣纸和水墨动态扫描素材；
- 从主程序 EcoSim._flow 的 flowOut/flowTo 直接生成速度场；当前实验使用解析曲线构造瀑布速度场；
- 与 InkFlow 主场景的生态状态和 3D 地形联动；
- WebGL 墨状态纹理；
- 真实浏览器画面、GPU 和设备帧率验收；
- 人工盲评和艺术质量量表。

## 5. 数值验证

运行方式：进入 research/ink-animation 目录后执行 npm test。

六项测试：

1. 水量和墨量账本守恒；
2. 下游流场推动水分质心向下移动；
3. 同一随机种子和操作产生完全一致的状态；
4. 非法输入被拒绝，不污染状态；
5. 游离墨在固定前随下游水流移动；
6. 纸纤维方向会使扩散沿纤维方向更强。

最近一次测试结果：**6/6 通过**。

一次独立 Node.js 数值基准（192×112 网格、250 步、约 10 个模拟时间单位）记录：

| 指标 | 结果 |
|---|---:|
| 水量相对账本误差 | 5.67×10⁻⁹ |
| 墨量相对账本误差 | 4.84×10⁻⁹ |
| 最小状态值 | 0 |
| 非有限值 | 0 |
| 平均单步耗时 | 1.70 ms/step |
| 本次 Node 执行吞吐 | 约 588 steps/s |

耗时只代表本次 Node.js 执行环境，不代表浏览器帧率或用户设备性能。质量守恒指标是数值正确性检查，不等同于艺术效果质量。

## 6. 本轮发现与下一步

### 发现

- 单独移动笔触和单独模拟墨水是两个不同问题；D 模式需要同时成立才有意义。
- 纸纤维方向会改变墨迹扩散方向，不能只用各向同性模糊。
- 瀑布的白色主体必须被保护，墨迹集中在边界和飞溅区域。
- 数值守恒通过不代表画面一定好看；必须继续做真实画面对照。

### 下一步优先级

1. 在真实浏览器中对 A/B/C/D 模式进行同种子、同构图截图比较；
2. 调整笔触数量、速度、浓淡和留白，避免“程序粒子感”；
3. 用真实水墨扫描素材替换程序化笔刷占位；
4. 将 EcoSim._flow 的水文通量转换为稳定的速度场，比较解析瀑布流与真实径流驱动的差异；
5. 再决定是否接入主程序和 3D 地形，不提前合并。
